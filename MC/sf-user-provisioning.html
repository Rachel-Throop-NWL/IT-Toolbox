Overview

Before You Begin

This guide covers end-to-end provisioning for a batch of Salesforce users starting from a list of Newell Employee IDs. The Public Group ID and Permission Set ID are already known. Workbench is the primary tool for both the SOQL query and the mass inserts.

PhaseToolWhat Happens
1 — Format Newell IDsExcelWrap each Newell ID in single quotes for use in the SOQL IN clause
2 — Query User ObjectWorkbenchQuery Newell_ID__c field on the User object; export Record IDs
3 — Update fileExcelAdd User Record IDs to the provisioning file
4 — Insert GroupMemberWorkbench (+ Data Loader alt)Assign each user to the Public Group
5 — Insert PermissionSetAssignmentWorkbench (+ Data Loader alt)Assign the Permission Set to each user
Step 1

Format Newell IDs for the SOQL Query

The starting file contains Newell Employee IDs, which map to the Newell_ID__c custom field on the Salesforce User object. Each ID must be wrapped in single quotes and separated by commas to be used in a SOQL IN clause.

Excel Formula

With Newell IDs in Column A, enter this formula in Column B:

="'"&A2&"',"

This produces output like:

'12345',
'67890',
'11223',

Copy the Column B output, paste into a text editor, and remove the trailing comma from the last entry. The list is ready to paste into the query below.

Step 2

Query the User Object in Workbench

Use Workbench to query the User object by Newell_ID__c and retrieve each user's Salesforce Record ID.

  1. Go to workbench.developerforce.com and log in with your Salesforce Administrator credentials. Select the correct Environment (Production or Sandbox) and click Login with Salesforce.
  2. From the top menu, go to Queries → SOQL Query.
  3. Paste the query below, replacing the placeholder values with your formatted Newell ID list from Step 1:
SELECT Id, Newell_ID__c, Name, Username, IsActive
FROM User
WHERE Newell_ID__c IN (
  '12345',
  '67890',
  '11223'
)
  1. Click Run. Confirm the row count matches your input list and that IsActive = TRUE for all returned users.
  2. Click Export Results to download the results as a CSV.
⚠️
Heads up If any Newell IDs are missing from the results, the user may be inactive, their Newell_ID__c field may not be populated, or they may not exist in this org. Resolve all gaps before proceeding to the mass inserts.
Step 3

Update the Provisioning File

Copy the Id column (Salesforce User Record ID) from the Workbench export into your provisioning file, matched to each Newell ID. The completed file should have these four columns before loading into Workbench:

ColumnDescriptionExample Value
Newell_ID__cNewell Employee ID (starting point)12345
Id (User Record ID)18-char Salesforce User Record ID from Workbench export005Xx0000001AbCDEF
Public Group IDID of the target Public Group (already known)00GXx000000XXXXX
Permission Set IDID of the target Permission Set (already known)0PSXx000000XXXXX
💡
Tip The Public Group ID and Permission Set ID are the same for every row. Enter the value once in the first row and fill down in Excel before saving as CSV.
Insert 1 of 2

GroupMember — Public Group Assignment

Insert a GroupMember record for each user to add them to the Public Group.

Required Column Mapping

CSV Column→Salesforce FieldNotes
Public Group ID→GroupIdSame value for every row
Id (User Record ID)→UserOrGroupIdUnique per user

Via Workbench (Primary)

  1. In Workbench, go to Data → Insert.
  2. Set Object Type to GroupMember.
  3. Click Choose File and select your provisioning CSV.
  4. Map the columns: Public Group ID → GroupId and Id (User Record ID) → UserOrGroupId.
  5. Click Insert Records. Review the results summary — successes and any failures will be listed.
Alternate Method — Data Loader
  1. Open Data Loader and click Insert. Select GroupMember as the object.
  2. Browse to your provisioning CSV and confirm the row count. Click Next.
  3. Map Public Group ID → GroupId and Id (User Record ID) → UserOrGroupId. Click Next, then Finish.
  4. Review the success and error log files after the job completes.
⚠️
Common Error A "duplicate value" error means the user is already a member of this group. This is not harmful — their membership is already in place and all other rows will still process.

  1. In Workbench, go to Data → Insert.
  2. Set Object Type to PermissionSetAssignment.
  3. Click Choose File and select your provisioning CSV.
  4. Map the columns: Permission Set ID → PermissionSetId and Id (User Record ID) → AssigneeId.
  5. Click Insert Records. Review the results summary.
Alternate Method — Data Loader
  1. Open Data Loader and click Insert. Select PermissionSetAssignment as the object.
  2. Browse to your provisioning CSV and confirm the row count. Click Next.
  3. Map Permission Set ID → PermissionSetId and Id (User Record ID) → AssigneeId. Click Next, then Finish.
  4. Review the success and error log files after the job completes.
⚠️
Common Error A "duplicate value" error means the user already has this Permission Set assigned. This is expected and not harmful.
