eBids — Business Requirements
What the business needs the system to do · Last updated Aug 6 2026 · Owner: Rachel Throop · Source: Business sessions with Sandra Smith and Karen Chavis

Bid Creation

Reps can create a bid record in Salesforce Must have
BR-01
A sales rep or coordinator can create a new bid record. The record captures the end user, the distributor(s), the products and pricing being requested, and the bid type.
Bid Source drives what type of bid is being created Must have
BR-02
A Bid Source field on the record determines the type:
  • Bid — pricing only, no rebate
  • Rebate Only — a rebate program only, no bid pricing. Gets a bid number. Lives in the same search screen as bids.
  • Bid + Rebate — both pricing and a rebate program on the same record
Rebate section is only visible when relevant Must have
BR-03
The rebate section on the bid record is hidden when Bid Source = Bid. It becomes visible and required when Bid Source = Rebate Only or Bid + Rebate. This keeps the record clean for bid-only submissions.
Bid Source can be changed after creation Must have
BR-04
A rep or coordinator can change Bid Source from Bid to Bid + Rebate after the record is created — for example, when a rebate program needs to be added to an existing bid. When this happens on an already-approved record, the system flags it for re-review.

Pricing

List price sourced from SAP into Salesforce Must have
BR-05
The system pulls list price from SAP so reps can see the starting price when building a bid. This is reference data only — no pricing changes are written back to SAP. All eBids is after-sales pricing.

GM% formula calculated and visible on the bid Must have
BR-06
The system calculates GM% per line item based on the pricing requested. The bid reviewer uses GM% to determine the appropriate approval routing — bids below 15% GM or below the hard floor require escalation.

Rebate Programs

Rebate programs entered via a simple entry screen Must have
BR-08
The rebate section presents a clean entry screen with dropdowns. The user selects the rebate program(s) — they do not create a new object or navigate away from the bid record. Selected programs are listed on the bid after entry.
All rebate programs require an approval process Must have
BR-09
Every rebate program — whether standalone or on a bid — goes through system routing for approval. Even rebates discussed and agreed offline must route through the system for audit purposes. The approval chain for rebates is different from bid pricing approval.

Approval Process

One approval process handles all scenarios Must have
BR-10
There is one approval process in Salesforce. The bid reviewer (coordinator) manually initiates approval and controls the approver list. The system does not auto-assign approvers. The bid reviewer follows the routing guidelines to determine who approves each submission.
Four approval scenarios must be supported Must have
BR-11
  • A — Bid only: bid pricing submitted and approved. Routing by dollar volume, region, GM%, and end user segment.
  • B — Rebate only: rebate program submitted without a bid. Gets a bid number. Lives in bid search screen.
  • C — Bid + rebate together: both submitted in one cycle. Follows rebate routing. Approved simultaneously.
  • D — Rebate added to an approved bid: bid was already approved. Rebate section is filled in later. Status returns to Under Review. Only the rebate portion re-routes for approval — bid pricing does not re-approve.
Approval history shows what was approved in each cycle Must have
BR-12
Each submission is logged with the approval type (Bid / Rebate Only / Bid + Rebate) so there is a clear audit trail. Sandra and the business team require this for compliance purposes.
Status reflects the current state of the record at all times Must have
BR-13
Statuses: Created → Under Review → Submitted for Approval → Rejected → Approved. When a rebate is added to an Approved record, status automatically returns to Under Review so the bid reviewer knows action is needed.

Amendments

Bids support multiple amendment cycles Must have
BR-14
A bid can have 10 or more amendments over its lifetime. After each amendment is approved, the rep must be able to request another amendment. The current build only supports one amendment cycle — this is a known gap that must be resolved.
Build gap · logged in SFDC-25926 · awaiting Dev solution
Distributors notified when an amendment is committed Must have
BR-15
When an amendment is committed and approved, distributors linked to the bid receive an automated notification that the bid has been updated. The notification does not need to include the details of what changed — just that the bid was updated.
