eBids Approval Process — Dev Spec Updated Aug 6 2026

For Vineet Kumar (Dev) · SFDC-25926 · Replaces July 2026 version · Rebate scenarios added

Context — what exists today

ItemCurrent state
Approval processOne approval process in Salesforce. Bid reviewer initiates manually and controls approvers.
Bid Source fieldPicklist already exists: Bid / Rebate Only / Bid + Rebate
Rebate sectionHidden until Bid Source = Rebate Only or Bid + Rebate — already works
Edit accessAnyone with edit access can change Bid Source after creation

Current statuses: Created → Under Review → Submitted for Approval → Rejected → Approved

The gap — what is missing

#GapImpact
1When Bid Source changes to Rebate Only or Bid + Rebate on an Approved record — status does not flip backBid reviewer has no signal that re-approval is needed
2Approval history does not capture what type was approved in each cycleNo audit trail of whether approval covered Bid, Rebate, or both
3No validation preventing submission when Bid Source = Rebate but rebate section is emptyApprovers can receive incomplete records

Change 1 — Status flip rule

When Bid_Source__c changes to Rebate Only or Bid + Rebate on a record that is already Approved, auto-flip the status to Under Review.

IF Bid_Source__c CHANGED
AND new value IN ('Rebate Only', 'Bid + Rebate')
AND Status__c = 'Approved'
THEN Status__c = 'Under Review'
This covers Scenario D — rebate added to an already-approved bid. The bid reviewer then reviews the rebate, updates approvers, and re-submits. No other status transitions change.
Open question: should the bid reviewer receive an email or in-app notification when this flip occurs? Pending Sandra's response. Build the status flip regardless — notification is additive.

Change 2 — Log approval type in history

When the record moves to Submitted for Approval, capture the current value of Bid_Source__c and write it to the approval history / activity log entry.

Bid Source at submissionHistory entry shows
BidSubmitted for Approval — Bid
Rebate OnlySubmitted for Approval — Rebate Only
Bid + RebateSubmitted for Approval — Bid + Rebate

No UI changes needed. This is an additional field on the existing history log entry.

Change 3 — Validation rule

Block submission when Bid Source indicates a rebate but the rebate section is empty.

IF Bid_Source__c IN ('Rebate Only', 'Bid + Rebate')
AND rebate section fields ARE EMPTY
THEN block submission

Error message:
"Rebate section is required when Bid Source is Rebate Only
or Bid + Rebate. Please complete the rebate section before
submitting."

What does NOT change

Approval process routing · Approver management (bid reviewer manual control) · Status labels · Object model (rebate stays as section on bid record) · Rebate section visibility logic · SAP (no writes — all after-sales pricing)

Acceptance criteria

1
When Bid Source changes to Rebate Only or Bid + Rebate on a record with Status = Approved → status auto-flips to Under Review
2
No status flip occurs if record is not yet Approved (Scenarios B and C above pass through normally)
3
Bid Source value is captured in the approval history log at time of each submission to Submitted for Approval
4
Validation error blocks submission when Bid Source = Rebate Only or Bid + Rebate but rebate section fields are empty
5
All existing status transitions remain unchanged
6
Rebate section visibility logic unchanged — still gated by Bid Source value
