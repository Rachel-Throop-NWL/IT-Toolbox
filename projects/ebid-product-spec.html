2 · Bid record — object model

The bid record is the core object. Pricing, rebate programs, approval status, and distributor assignments all live on or relate to the bid record. Rebate is a section on the bid record — not a separate object.

Bid Source — the governing field

Bid Source is a picklist that controls section visibility and determines which approval scenario applies. It is set at creation and can be changed by anyone with edit access.

Bid Source valueBid pricing sectionRebate sectionApproval scenario
BidVisible · requiredHiddenScenario A
Rebate OnlyHiddenVisible · requiredScenario B
Bid + RebateVisible · requiredVisible · requiredScenario C or D

Business rules

Validation — empty rebate sectionIf Bid Source = Rebate Only or Bid + Rebate AND rebate section empty → block submission with error message

3 · Approval process

One approval process. Bid reviewer initiates manually and controls approvers. No automated routing. See Approval Scenarios page for full step-by-step flows.

4.2 · Amendment flow
BUILD GAP IDENTIFIED

After the first amendment is approved, there is no option to request a subsequent amendment. Bids can have 10 or more amendments.

Requirements: (1) bid must support multiple amendment cycles throughout lifecycle. (2) When an amendment is committed and approved, distributors receive automated notification that bid was updated — content not required, notification only.
